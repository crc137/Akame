## Установка

```bash
curl -sSL https://raw.coonlink.com/cloud/Akame/install.sh | sudo sh
```

Нужны две иконки на том же сервере: `quiet.png` и `threat.png` (`.ico` тоже работает). Размер любой квадратный — панель масштабирует сама.

Установщик определяет пользователя рабочего стола, ставит компоненты, включает systemd-юниты, добавляет элемент на панель Xfce и задаёт первый baseline. Дополнительных шагов нет.

Однострочная форма (`curl … | sudo sh`) работает, но отдаёт root тому, что вернёт сервер, без всякой проверки. Это самое слабое место проекта, и оно относится к способу доставки, а не к коду. Для одной машины надёжнее просто скопировать файл через `scp`.

### Удаление

```bash
curl -sSL https://raw.coonlink.com/cloud/Akame/install.sh | sudo sh -s -- --uninstall
```

Удаляет юниты, бинарники, правило sudoers, конфиг, состояние, элемент панели и иконки.


## Что проверяется

**`threat`:**

- история входов уменьшилась (вывод `last` короче прежнего или самая старая запись сдвинулась вперёд)
- `lastlog2.db` пропал или стал меньше
- `pam_wtmpdb.so` или `pam_lastlog2.so` больше не активны в `common-session` — запись входов отключена
- изменились `/etc/sudoers`, `/etc/sudoers.d` или `/root/.ssh`
- появилась вторая учётная запись с uid 0
- число неудачных попыток достигло `FAIL_ALERT` с последнего сброса
- файл статуса старше 180 секунд или `akame-follow` не запущен

**Тоже `threat`, но в подсказке помечается как меньшая аномалия:**

- изменились `/etc/pam.d`, `/etc/passwd`, `/etc/group`, `/etc/shadow`
- история журнала ротирована или очищена

Живой наблюдатель читает журнал потоком, поэтому неверный пароль отражается примерно за секунду. Таймер раз в минуту прогоняет полную проверку как подстраховку.


## Telegram

Необязателен. Настраивается через иконку на панели → **Settings**, либо:

```bash
sudo akame-config '<токен бота>' '<chat id>' 1
```

Chat id: сначала напиши боту сообщение (Telegram запрещает ботам писать первыми), затем

```bash
curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | grep -o '"id":[0-9-]*' | head -3
```

Telegram намеренно работает **только на чтение**: уведомления и `Status`. Сброс возможен только локально — иначе токен бота становится удалённым способом гасить те же тревоги, которые он поднимает.

Суточный heartbeat сообщает `alive`, текущий уровень, счётчик и uptime. Включается автоматически, как только заданы токен и chat id. Уведомление отправляется при смене уровня, поэтому изменения конфигурации тоже дают сигнал, а не только неудачные входы.

В сообщениях содержатся строки журнала — там могут быть имена пользователей и IP-адреса. Это осознанная передача логов наружу, но знать об этом стоит.


## Компоненты

| Путь | От кого | Назначение |
|---|---|---|
| `/usr/local/sbin/akame-check` | root | проверки; пишет `/run/akame/status` |
| `/usr/local/sbin/akame-follow` | root | читает журнал потоком, реакция ~1 с |
| `/usr/local/sbin/akame-notify` | root | одно уведомление в Telegram при смене уровня |
| `/usr/local/sbin/akame-heartbeat` | root | суточный признак жизни |
| `/usr/local/sbin/akame-tgbot` | root | обработка кнопки `Status` |
| `/usr/local/sbin/akame-config-set` | root | единственный писатель конфига; читает stdin, аргументов не принимает |
| `/usr/local/sbin/akame-config-show` | root | сообщает, задан ли токен — сам токен не отдаёт |
| `/usr/local/sbin/akame-config` | root | CLI-обёртка над двумя предыдущими |
| `/usr/local/bin/akame-icon` | пользователь | скрипт genmon — выбирает иконку |
| `/usr/local/bin/akame-ui` | пользователь | окно по левому клику: попытки, Reset, Settings |

Юниты: `akame.timer` (полная проверка раз в минуту), `akame-follow.service` (живой), `akame-heartbeat.timer` (суточный), `akame-tgbot.service`.

Состояние в `/var/lib/akame/state` (0700), конфиг в `/etc/akame/conf` (0600), статус в `/run/akame/status` (0640).


## Модель привилегий

Пользователю рабочего стола доступны ровно три команды, без wildcard:

```
NOPASSWD: /usr/local/sbin/akame-check --ack
NOPASSWD: /usr/local/sbin/akame-config-set ""
NOPASSWD: /usr/local/sbin/akame-config-show ""
```

Пустые кавычки принципиальны: в sudoers команда, записанная без аргументов, разрешает *любые* аргументы. Обе вспомогательные команды дополнительно отвергают аргументы сами.

Конфиг нигде не исполняется как shell. Значения читаются через `sed` и проверяются при записи (токен — `<цифры>:<base64url>`, chat id — целое число), поэтому подставленное значение не может стать кодом. Токен попадает в `curl` через `-K -` со stdin и не появляется в argv ни одного процесса.


## Настройки

`/etc/akame/conf`:

| Ключ | По умолчанию | Значение |
|---|---|---|
| `TG_TOKEN` | пусто | токен бота; пусто — Telegram отключён |
| `TG_CHAT` | пусто | chat id |
| `FAIL_ALERT` | `1` | попыток до `threat` |
| `TG_MIN_INTERVAL` | `60` | секунд между сообщениями |
| `UI_USER` | задаётся при установке | владелец группы файла статуса |

`FAIL_ALERT` меняется из GUI, остальное — правкой файла от root.


## Повседневные команды

```bash
cat /run/akame/status              # текущее состояние
sudo akame-check --ack             # сброс после того, как посмотрел
systemctl status akame-follow      # жив ли живой наблюдатель
journalctl -u akame-tgbot -n20     # проблемы telegram-бота
```

Иконка переключается в `threat` после любого `apt`, который тронул `/etc/pam.d` — это работа проверки целостности, а не ложное срабатывание. Посмотри, *что именно* изменилось, и сбрось.


## Известные ограничения

- Только Debian/Kali с `wtmpdb` и `lastlog2`. На системах с классическим `wtmp` часть проверок будет в `threat` постоянно.
- Элемент панели требует живой сессии Xfce; при установке из VT этот шаг пропускается.
- `akame-ui` читает журнал от имени пользователя рабочего стола — если он не в группе `adm`, список попыток будет пустым. Решение: `usermod -aG adm <пользователь>`.
- Ротация журнала может один раз вызвать проверку «история очищена».
- Иконки скачиваются по HTTPS без проверки целостности.
- Любой, у кого есть root, может заглушить всё. См. примечание в README.
